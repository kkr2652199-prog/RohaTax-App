# 규칙 우선순위 매트릭스 (Rule Priority Matrix)

## 📋 개요
변환 시스템에서 규칙 충돌 시나리오별 해결 방법을 정의한 우선순위 매트릭스입니다.

---

## 🎯 규칙 우선순위 정의 (Rule Priority Definition)

### 1순위: 시트 선택 규칙 (Sheet Selection Rules)
**우선순위**: 최고 (Highest)
**적용 시점**: 파일 업로드 후
**충돌 시나리오**: 여러 시트가 동일한 점수를 가질 때
**해결 방법**: Fast-Path > 총배달 금액 > 점수제 > 알파벳 순서

### 2순위: 7종 컬럼 매칭 규칙 (7-Column Matching Rules)
**우선순위**: 높음 (High)
**적용 시점**: 시트 선택 후
**충돌 시나리오**: 여러 컬럼이 동일한 키워드를 가질 때
**해결 방법**: 금지어 > 키워드 > 부분 문자열 > 첫 번째 매칭

### 3순위: 공급받는자 추출 규칙 (Recipient Extraction Rules)
**우선순위**: 중간 (Medium)
**적용 시점**: 컬럼 매칭 후
**충돌 시나리오**: 동일한 사업자번호의 여러 데이터가 있을 때
**해결 방법**: 가족통합 > 중복 제거 > 최신 데이터 우선

### 4순위: 템플릿 기입 규칙 (Template Input Rules)
**우선순위**: 낮음 (Low)
**적용 시점**: 데이터 추출 후
**충돌 시나리오**: 템플릿 필드에 여러 값이 있을 때
**해결 방법**: 공급자 > 공급받는자 > 금액 정보 > 기본값

## 🔄 충돌 시나리오별 해결 방법 (Conflict Resolution by Scenario)

### 시나리오 1: 시트 선택 충돌
**상황**: 여러 시트가 동일한 점수를 가짐
**규칙 충돌**: Fast-Path vs 점수제 vs 총배달 금액
**해결 방법**:
1. **1순위**: Fast-Path 시트 확인 ("발행용", "정산서", "공유콜")
2. **2순위**: 총배달 금액이 가장 높은 시트 선택
3. **3순위**: 점수제 시스템으로 최고 점수 시트 선택
4. **4순위**: 알파벳 순서로 첫 번째 시트 선택

**코드 위치**: `core/file_parser.py` 라인 484-900
**핵심 로직**:
```python
# 1순위: Fast-Path 시스템
priority_sheet = self._find_priority_sheet(workbook, self.required_keywords)
if priority_sheet:
    return priority_sheet  # 즉시 선택

# 2순위: 총배달 금액 우선 선점
delivery_sheets = [r for r in sheet_results if r.get('delivery_amount', 0) > 0]
if delivery_sheets:
    delivery_sheets.sort(key=lambda r: (r.get('delivery_amount', 0), r.get('sheet_name', '')), reverse=True)
    best_result = delivery_sheets[0]

# 3순위: 점수제 시스템
if sheet_result['score'] > best_score:
    best_score = sheet_result['score']
    best_result = sheet_result
```

### 시나리오 2: 컬럼 매칭 충돌
**상황**: 여러 컬럼이 동일한 키워드를 가짐
**규칙 충돌**: 금지어 vs 키워드 vs 부분 문자열
**해결 방법**:
1. **1순위**: 금지어 체크 (잘못된 매칭 차단)
2. **2순위**: 정확한 키워드 매칭
3. **3순위**: 부분 문자열 포함 매칭
4. **4순위**: 첫 번째 매칭된 컬럼 선택

**코드 위치**: `core/file_parser.py` 라인 1638-1656
**핵심 로직**:
```python
# 1순위: 금지어 체크
if forbidden_keywords_map and field_type in forbidden_keywords_map:
    forbidden_keywords = forbidden_keywords_map[field_type]
    is_forbidden = any(forbidden_keyword.lower() in cell_text for forbidden_keyword in forbidden_keywords)
    if is_forbidden:
        continue  # 금지어가 포함된 컬럼은 해당 필드에서 제외

# 2순위: 키워드 매칭
for keyword in keywords:
    if keyword_lower in cell_text:
        matched_fields.add(field_type)
        break
```

### 시나리오 3: 부가세 앞칸 규칙 충돌
**상황**: 부가세 앞칸이 총합계가 아닐 때
**규칙 충돌**: 부가세 앞칸 규칙 vs 키워드 매칭
**해결 방법**:
1. **1순위**: 부가세 앞칸 규칙 (10:1 비율 검증)
2. **2순위**: 키워드 매칭으로 총금액 컬럼 찾기
3. **3순위**: 부분 문자열로 금액 관련 컬럼 찾기
4. **4순위**: 첫 번째 숫자 컬럼 선택

**코드 위치**: `core/file_parser.py` 라인 1237-1270
**핵심 로직**:
```python
# 1순위: 부가세 앞칸 규칙
dad_col = self._validate_dad_column_before_mom(sheet, col_num, header_row)
if dad_col is not None:
    column_mapping['dad_amount'] = dad_col
    return dad_col

# 2순위: 키워드 매칭
if 'dad_amount' not in column_mapping:
    dad_keywords = ['총', '합계', '금액', '요금', '배달', '총금액', '총합']
    for col_num in range(1, sheet.max_column + 1):
        cell_value = str(sheet.cell(header_row, col_num).value).strip().lower()
        if any(keyword in cell_value for keyword in dad_keywords):
            column_mapping['dad_amount'] = col_num
            break
```

### 시나리오 4: 가족통합 충돌
**상황**: 동일한 사업자번호의 여러 데이터가 있을 때
**규칙 충돌**: 가족통합 vs 중복 제거 vs 최신 데이터 우선
**해결 방법**:
1. **1순위**: 가족통합 (동일 사업자번호 그룹화)
2. **2순위**: 중복 제거 (동일한 데이터 제거)
3. **3순위**: 최신 데이터 우선 (최근 날짜 데이터 선택)
4. **4순위**: 첫 번째 데이터 선택

**코드 위치**: `core/file_parser.py` 라인 1013-1014
**핵심 로직**:
```python
# 1순위: 가족 통합 로직 적용
families = self._merge_family_data(raw_families)

# 가족통합 함수 내부
def _merge_family_data(self, raw_families):
    # 동일 사업자번호 그룹화
    grouped = {}
    for family in raw_families:
        business_number = family.get('business_number', '')
        if business_number not in grouped:
            grouped[business_number] = []
        grouped[business_number].append(family)
    
    # 중복 제거 및 최신 데이터 우선
    merged_families = []
    for business_number, families in grouped.items():
        # 중복 제거
        unique_families = self._remove_duplicates(families)
        # 최신 데이터 우선
        latest_family = max(unique_families, key=lambda x: x.get('date', ''))
        merged_families.append(latest_family)
    
    return merged_families
```

### 시나리오 5: 템플릿 기입 충돌
**상황**: 템플릿 필드에 여러 값이 있을 때
**규칙 충돌**: 공급자 vs 공급받는자 vs 금액 정보 vs 기본값
**해결 방법**:
1. **1순위**: 공급자 정보 입력
2. **2순위**: 공급받는자 정보 입력
3. **3순위**: 금액 정보 입력
4. **4순위**: 기본값 사용

**코드 위치**: `core/template_manager.py`
**핵심 로직**:
```python
# 1순위: 공급자 정보 입력
def input_supplier_info(self, template, supplier_data):
    # 공급자 정보 우선 입력
    template['supplier_name'] = supplier_data.get('name', '')
    template['supplier_business_number'] = supplier_data.get('business_number', '')
    template['supplier_address'] = supplier_data.get('address', '')

# 2순위: 공급받는자 정보 입력
def input_recipient_info(self, template, recipient_data):
    # 공급받는자 정보 입력
    template['recipient_name'] = recipient_data.get('name', '')
    template['recipient_business_number'] = recipient_data.get('business_number', '')
    template['recipient_address'] = recipient_data.get('address', '')

# 3순위: 금액 정보 입력
def input_amount_info(self, template, amount_data):
    # 금액 정보 입력
    template['supply_amount'] = amount_data.get('supply_amount', 0)
    template['vat_amount'] = amount_data.get('vat_amount', 0)
    template['total_amount'] = amount_data.get('total_amount', 0)

# 4순위: 기본값 사용
def use_default_values(self, template):
    # 기본값 사용
    template['supplier_name'] = template.get('supplier_name', '기본 공급자')
    template['recipient_name'] = template.get('recipient_name', '기본 공급받는자')
    template['supply_amount'] = template.get('supply_amount', 0)
```

## 🔧 충돌 해결 프로세스 (Conflict Resolution Process)

### 1단계: 충돌 감지 (Conflict Detection)
**목적**: 규칙 충돌 상황을 자동으로 감지
**방법**: 각 단계에서 여러 결과가 나올 때 충돌로 판단
**코드**: 각 함수에서 결과 개수 확인

### 2단계: 우선순위 적용 (Priority Application)
**목적**: 정의된 우선순위에 따라 해결 방법 적용
**방법**: 1순위부터 4순위까지 순차적으로 적용
**코드**: 우선순위별 조건문 실행

### 3단계: 결과 검증 (Result Validation)
**목적**: 충돌 해결 결과의 유효성 검증
**방법**: 결과가 유효한지 확인하고, 무효하면 다음 우선순위 적용
**코드**: 결과 검증 함수 호출

### 4단계: 로깅 및 보고 (Logging and Reporting)
**목적**: 충돌 해결 과정을 로그로 기록
**방법**: 충돌 상황과 해결 방법을 상세히 로깅
**코드**: 로깅 함수 호출

## 🎯 모범 사례 (Best Practices)

### 충돌 예방
**한 문장**: 규칙 충돌을 사전에 예방하는 것이 가장 좋습니다.
**방법**: 명확한 우선순위 정의, 충돌 시나리오 사전 분석, 테스트 케이스 작성

### 충돌 해결
**한 문장**: 충돌 발생 시 정의된 우선순위에 따라 해결하세요.
**방법**: 1순위부터 4순위까지 순차적으로 적용, 결과 검증, 로깅

### 성능 최적화
**한 문장**: 충돌 해결 과정에서 성능을 최적화하세요.
**방법**: 불필요한 검사 생략, 캐싱 활용, 병렬 처리

### 유지보수
**한 문장**: 충돌 해결 로직을 정기적으로 검토하세요.
**방법**: 새로운 충돌 시나리오 분석, 우선순위 재검토, 테스트 케이스 업데이트
